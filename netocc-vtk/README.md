# netocc-vtk

NetOcc.Vtk: OCCT shapes in [VTK](https://vtk.org) scenes, next to simulation results. C# bindings for OCCT 8.0.1's TKIVtk (`IVtk`, `IVtkOCC`, `IVtkVTK`, `IVtkTools`) on [NetOcc](../netocc-core) and [NetVtk](https://github.com/paulbuechner/netvtk), the C# bindings for VTK 9.7.1. OCCT's names unchanged, VTK's classes NetVtk's (`Vtk`); NetOcc's frameworks and RIDs.

Tests green on win-x64 and win-x86 (net10.0, net8.0, net48) and on linux-x64 (net10.0, net8.0, in Docker); CI runs them on all four RIDs, osx-arm64 included (the rendering ones on Linux only).

## Install

```bash
dotnet add package NetOcc.Vtk
```

It brings NetOcc of its own version and one NetVtk release along:

| Package | Holds |
|---|---|
| `NetOcc.Vtk` | the assembly; depends on `NetOcc`, `NetVtk` and the runtime packages |
| `NetOcc.Vtk.runtime.<rid>` | `NetOccVtk` (SWIG's wrappers) and OCCT's TKIVtk |
| `NetOcc.runtime.<rid>` | OCCT's other libraries |
| `NetVtk.runtime.<rid>` | VTK's libraries |

- `IVtkTools_ShapeDataSource` is a `vtkPolyDataAlgorithm`: an `IVtkOCC_Shape` in any VTK pipeline, a result field on its faces.
- `IVtkTools_ShapePicker` picks shapes and their faces, edges and vertices in a `vtkRenderer`.

Examples: [VTK scenes](https://paulbuechner.github.io/netocc/articles/vtk.html), each a test on the packed NetOcc.Vtk.

## Monorepo

Part of the [netocc monorepo](../README.md):

| Folder | Role |
|---|---|
| [netocc-generator](../netocc-generator) | writes the modules here (`config/vtk.yaml`, `--core ../netocc-vtk --netvtk <NetVtk's swig/>`) |
| [netocc-core](../netocc-core) | builds OCCT with TKIVtk (`build.py occt`), packs the NetOcc this builds on; its `build.py` is imported here |
| netocc-vtk | the modules, NetOccVtk, the assembly, tests, packages, a WPF demo |

## One VTK

TKIVtk is compiled against VTK's headers and runs on NetVtk's VTK libraries, so both must be the same build:

- **Registry:** netocc-core's `vcpkg-configuration.json` takes `vtk` from NetVtk's vcpkg registry, its `baseline` a NetVtk release's commit, its `reference` that release's branch (vcpkg reads the version database there: `next` for a prerelease); `vcpkg.json` asks for NetVtk's VTK features (`cgns`, `exodus`, `volume`).
- **Triplets:** netocc-core's are NetVtk's, byte for byte: vcpkg computes the same ABI hash, and either repository's binary cache restores the other's VTK.
- **`NetVtk.props`** names the NetVtk release of the registry's commit, and `vcpkg.json`'s `vtk` override its VTK version and port-version: move all three together.
- **At run time** NetOcc.Vtk has NetVtk load VTK first, then loads NetOccVtk through NetOcc's loader and checks that the VTK build it was compiled against (`9.7.1#1`: VTK's version and NetVtk's port-version) is the one NetVtk carries (`Vtk.VtkBuild.Require`, which throws where it isn't).

## Build

Needs netocc-core's prerequisites ([Building from source](https://paulbuechner.github.io/netocc/articles/building.html)) and its build: NetOcc.Vtk references its NetOcc project, and its pack depends on the NetOcc packed there (`>=` its version). CI and releases pack both at one version; a local pack gets a version of its own (`-local.<time>`), since NuGet keeps the first copy of a version it extracted.

```bash
(cd ../netocc-core && python build.py occt --triplet x64-windows && python build.py generate \
  && python build.py native --triplet x64-windows && python build.py pack --rids win-x64)
python build.py generate                        # SWIG over the modules -> build/generated (restores NetVtk first)
python build.py native --triplet x64-windows    # NetOccVtk + TKIVtk -> artifacts/runtimes/win-x64/native
python build.py test --arch x64                 # net10.0, net8.0, net48; --no-rendering without OpenGL
python build.py pack --rids win-x64             # NetOcc.Vtk + NetOcc.Vtk.runtime.win-x64 -> artifacts/packages
python build.py test-package --arch x64         # the packed NetOcc.Vtk, consumed like an app
dotnet build demo/NetOcc.Vtk.Viewer.Wpf -c Release
```

NetVtk comes from nuget.org (the release `NetVtk.props` names), or from a folder of packed NetVtk: `--netvtk-packages <dir>`, `NETVTK_PACKAGES`, or a sibling `../../netvtk` checkout's `netvtk-core/artifacts/packages`.

## Layout

| Path | Content |
|---|---|
| `src/SWIG_files/wrapper`, `headers`, `modules.json`, `classes.json` | generated by netocc-generator (`config/vtk.yaml`) |
| `src/SWIG_files/extras/IVtk.i` | hand-written companion: the VTK build TKIVtk was compiled against (`%netvtk_build`) |
| `src/NetOcc.Vtk` | the C# project: SWIG's proxies (from `build/generated`), the native loader; `README.md` is the package's (nuget.org) |
| `pack` | `NetOcc.Vtk.runtime.<rid>`: natives, license notices, .NET Framework copy targets |
| `test/NetOcc.Vtk.Tests` | NUnit tests: shapes as VTK algorithms, picking, the VTK build |
| `test/NetOcc.Vtk.PackageTests` | the packed NetOcc.Vtk from `artifacts/packages` (`build.py test-package`) |
| `demo/NetOcc.Vtk.Viewer.Wpf` | a part with a temperature on it, a scalar bar, faces picked by a click |
| `NetVtk.props` | the NetVtk release NetOcc.Vtk builds on |

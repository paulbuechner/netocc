# Move NetOcc to OCCT $version

The bindings follow OCCT. netocc-gen stamps the version it generated from into every module (`generated by netocc-gen from OCCT x.y.z`), `netocc-core/vcpkg.json` builds the natives from the same, and `build.py` refuses a mismatch. The first release for $version is `$version.1`: `build.py` starts the revision over.

The order: baseline, OCCT through vcpkg, bootstrap, generate, fixes, SWIG, natives and tests, the version everywhere, release. Every fix goes into netocc-gen, its `config/`, netocc-core's typemap library (`src/SWIG_files/common/*.i`) or a companion (`extras/<Pkg>.i`), never into generated files (`.i`, `_module.hxx`, `.g.cs`). The rules behind them are in the three CLAUDE.md files, the stories behind the rules in the documentation's Development pages (`netocc-documentation/articles/pitfalls.md`, `design.md`), and `/regenerate` is the inner loop. Logs go into each folder's `log/`. Commit only when the user asks.

## 1. Baseline, on the current OCCT

- All green: netocc-gen's tests, `build.py test --arch x64` and `--arch x86`.
- Keep what to compare with (`log/` is gitignored):

  ```bash
  cp -r netocc-generator/log/skips netocc-generator/log/skips-<old>    # the last generate's skip logs
  cp netocc-core/src/SWIG_files/{modules,classes}.json netocc-core/log/
  ```
- Note the counts: packages in `modules.json`, types in `classes.json`, skips (`cat netocc-generator/log/skips/*.txt | wc -l`), the test counts, the members `build.py docs` documents.
- Read OCCT's release notes for $version: packages and headers removed, renamed or moved, new toolkits, deprecations, reworked APIs. A patch release rarely moves anything, a minor or major one may. OCCT 8 moved the collection aliases, made `Standard_Failure` a `std::exception` and `TopoDS::Face` a namespace function.

## 2. OCCT through vcpkg

- vcpkg must have $version: a microsoft/vcpkg commit whose `versions/o-/opencascade.json` lists it (`gh api "repos/microsoft/vcpkg/commits?path=ports/opencascade&per_page=5"`). No port yet: wait, or ask the user before writing an overlay port.
- Pin the same commit and version everywhere:
  - `netocc-core/vcpkg-configuration.json`: `baseline`, which is also the vcpkg tool's commit in CI (`.github/actions/occt`) and the Linux Dockerfile, so its scripts match the ports;
  - `netocc-core/vcpkg.json`: the `opencascade` override;
  - `netocc-core/CMakeLists.txt`: `find_package(OpenCASCADE $version EXACT CONFIG REQUIRED)`.
- Build: x64 takes about an hour, x86 longer.

  ```bash
  cd netocc-core
  python build.py occt --triplet x64-windows > log/occt-x64.log 2>&1
  python build.py occt --triplet x86-windows > log/occt-x86.log 2>&1
  ```
- The overlay triplets (`netocc-core/vcpkg/triplets/`) build release only and keep OCCT's precondition checks (`BUILD_RELEASE_DISABLE_EXCEPTIONS=OFF`, per port). If the port renamed its options, fix the triplets; a changed triplet rebuilds OCCT.
- The port's patches: `netocc-core/NOTICE` names the corresponding source (tag `V<x_y_z>`) and the OCCT file vcpkg's patches change (`Image_AlienPixMap.cxx` for 8.0.1). Check the new port's `ports/opencascade/*.patch`, update `NOTICE`.
- netocc-gen's inputs are now the sources `netocc-core/.vcpkg/buildtrees/opencascade/src/V<x_y_z>-<hash>.clean` (`--occt-src`), the headers `netocc-core/.vcpkg/installed-x64-windows/x64-windows/include/opencascade` (`--occt-include`) and the DLLs in `../../bin` from there (the export check: generate on Windows).

## 3. Toolkits

```bash
cd netocc-generator
dotnet run --project src/NetOcc.Generator -- bootstrap --occt-src <sources>
```

`bootstrap` rewrites `config/toolkits.yaml` from OCCT's `MODULES.cmake`, `TOOLKITS.cmake` and `PACKAGES.cmake`; never edit it by hand. Review its diff: packages and toolkits new, gone, renamed. Then `config/modules.yaml`:

- New packages of the modules and toolkits it names come along. A new Visualization toolkit needs a decision: wrapped are TKService, TKV3d, TKOpenGl (the driver only) and TKMeshVS.
- Entries naming what's gone (`exclude_packages`, `exclude_classes`, `exclude_methods`, `classes`, `prelude`, `value_types`): drop them.
- `alias_packages` (TColgp, TColGeom, TColGeom2d): are OCCT's aliases still in `src/Deprecated/NCollectionAliases/`?
- `modules.json` groups the packages per OCCT module into one native library each, and a Windows DLL exports at most 65535 functions. A module that outgrows that fails to link (LNK1189) and needs a second library.

## 4. Generate

Update the paths in `netocc-generator/CLAUDE.md` (Commands), then run `/regenerate` with them. For an upgrade:

- **The diff is large.** Review it by kind: modules new and gone (`git diff --stat -- netocc-core/src/SWIG_files/wrapper`), `modules.json` and `classes.json` against the baseline copies, then the packages with the most changes.
- **Skips:** `diff -r log/skips-<old> log/skips`. A new reason is a C++ construct the mapping doesn't know: map it where the contract allows (netocc-generator/CLAUDE.md, Mapping rules), or leave it skipped with its reason. By reason: `cat log/skips/*.txt | sed -E 's/^[^:]*: //' | sort | uniq -c | sort -rn`. `python skips.py` in netocc-documentation then rewrites `articles/skipped.md`; it fails on skips nothing accounts for.
- **Parse errors** go to the skip logs too (`'X.pxx' file not found`, a header that doesn't compile alone). A header that misses an include of OCCT's gets a `prelude` on the declaring package; one OCCT doesn't install takes the headers after it along.
- **Hand-written parts** that name OCCT's members: companions `netocc-core/src/SWIG_files/extras/*.i` (`%extend`, renames, keeps), value-type partials `netocc-core/src/NetOcc/<Pkg>/<Type>.cs` with `value_types`, and the typemap library for new standard library types. SWIG or compiler errors after the generate usually point there.

## 5. SWIG, natives, tests

```bash
cd netocc-core
python build.py generate > log/generate.log 2>&1                  # fails on Warning 516, a base-dropping 401, SWIGTYPE_*
python build.py native --triplet x64-windows > log/native-x64.log 2>&1   # and x86-windows
python build.py test --arch x64 > log/test-x64.log 2>&1           # and --arch x86: every framework, net35 on CLR 2
```

- **Link errors:** members OCCT declares but doesn't export, vtables the DLLs don't export, destructors that don't link. netocc-gen checks the DLLs' export tables: extend the check rather than excluding members one by one.
- **Test failures:** a test in `test/NetOcc.Tests` may use an API OCCT changed. Move it to the new API; never weaken it until it passes.
- **IntelliSense:** `python build.py docs --triplet x64-windows`, its member count against the baseline.
- **Packages and their users:** `python build.py pack --rids win-x64,win-x86`, `test-package --arch x64` and `--arch x86`. Then the documentation's samples (`dotnet test netocc-documentation/samples -c Release`) and the demos (`dotnet build` then `dotnet test --no-build` on `netocc-demos/NetOcc.Demos.slnx`). The samples call real APIs: fix those OCCT changed, and the articles that describe them.
- **Linux:** `netocc-core/docker/linux-x64.Dockerfile`; its volume rebuilds OCCT once, about 25 minutes. macOS: CI only.
- **Generated files current:** `generate --check` in netocc-generator.

## 6. Everything that names the version

Generated files get the new stamp from netocc-gen. The rest: `git grep -n "<old x.y.z>"` and `git grep -n "V<old x_y_z>"` outside generated files. For 8.0.1 those were:

- `README.md` (the text, the OCCT badge), `netocc-core/src/NetOcc/README.md` (nuget.org), the descriptions in `netocc-core/src/NetOcc/NetOcc.csproj` and `netocc-core/pack/NetOcc.runtime.csproj`;
- the CLAUDE.md files, and the READMEs of netocc-core and netocc-generator;
- `netocc-documentation`: `index.md`, `articles/` (introduction, architecture, building), `classes.py` (`REFMAN`; check the manual exists at `https://dev.opencascade.org/doc/occt-<version>/refman/html/`. Those URLs answer 301 to `occt3d.com` (in 2026: `https://occt3d.com/dev/doc/refman/html/`), so sample pages with `curl -sL -o /dev/null -w '%{http_code}'`: a missing page ends in 404);
- `netocc-core/NOTICE` (tag, patches).

Then in netocc-documentation: `python classes.py` and `dotnet docfx docfx.json --warningsAsErrors`.

A changelog entry for package users: `python build.py change changed "Bindings for OCCT $version: ..."`, with what they see change (APIs OCCT removed or renamed, packages newly wrapped).

## 7. Release

`python build.py version` now gives `$version.1-local.<time>`. Continue with `/release`: the release PR makes `$version.1`. The first CI run after new pins is cold, about an hour, since the vcpkg caches don't match.

## What broke before

From the move to OCCT 8 and from growing the generator to all packages. The rules handling each are in the CLAUDE.md files; expect more of the same kinds.

- **OCCT 8's API moves:** `Standard_Failure` derives from `std::exception` (its type name from `ExceptionType()`); the collection aliases moved to `src/Deprecated/NCollectionAliases/`, parsed with each package, so `TColgp`, `TColGeom` and `TColGeom2d` stopped being packages; signatures spell `occ::handle<T>`, `double`, `bool`; namespace functions (`TopoDS::Face`) became static shim classes; evaluation results became plain-data structs.
- **libclang:** a missing include ends a parse silently; bugs in inline bodies show only when MSVC compiles the wrapper; template arguments come canonical (`size_t` differs per platform); enumerators sign-extend (`UnsignedInitVal`); layouts are win-x64's, so no `size_t`, `long` or bit fields in plain data; a template instance nothing instantiates has no members.
- **Linking:** members declared `Standard_EXPORT` but never defined; MSVC destructors mangle as `??_D`, the DLLs export `??1`; inline constructors of polymorphic classes emit vtables the DLLs don't export; placement-only `operator new`.
- **SWIG:** typemaps apply to later declarations only; Warning 516 drops overloads C# could tell apart (`typecheck` typemaps; instance members shadowed by static overloads); Warning 401 from import order (netocc-gen imports base packages first); `%extend` bodies are preprocessed without `_WIN32`; out typemaps reach constructors (`T* const`); long instance names exceed the path limit (hashed).
- **Generated on Windows, built everywhere:** Windows-only headers stay out; typedefs that differ per platform (`Aspect_Drawable`) are kept by name.
- **Lifetimes:** a class keeping a reference to an argument needs a keep; the parser's `ClassModel.Held` finds new ones on its own. Borrowed proxies keep their owner alive.
- **Crashes where C++ crashes** (members of a null handle) get a warning in the documentation, no guard.
